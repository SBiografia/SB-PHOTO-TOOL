## 판단

## 콜라주 화면 구조

`ImageEditActivity.G()`가 `activity_edit`를 사용하고, `onCreate()`가 상단 도구, 중앙 사진·배경·낙서 레이어, 전체 도구 목록, 사진 선택 메뉴를 연결한다. [E03, E04]

```text
상단: 뒤로 / 실행 취소·다시 실행 / 설정 / 저장
                 ↓
중앙: 배경 + 사진·글자·장식 + 낙서 / 선택 표시·교환 안내
                 ↓
하단: 전체 도구 또는 현재 선택한 항목의 조작 메뉴
                 ↓
도구별 설정: 썸네일 목록 / 슬라이더 / 적용·취소
```

이 구조에서 참고할 점은 **캔버스를 유지하면서 하단 설정 영역을 바꾸는 것**이다. 별도 자유형 편집기 `ImageFreeActivity`도 존재하므로 GridArt가 모든 편집 모드를 하나의 Activity로 처리한다고 해석하면 안 된다. [E04, E08]

### 1. 전체 설정과 선택 사진 조작을 분리

`EditToolsMenuRecyclerView`는 가로 `LinearLayoutManager`를 사용하고 모드에 따라 목록을 바꾼다. `dt0` 메뉴 선언에는 템플릿, 레이아웃, 마진, 비율, 배경, 테두리/윤곽선, 글자, 필터, 사진 추가, 스티커, 낙서 등이 있다. AI 자르기·제거·향상·효과 같은 항목도 선언되어 있으나 모든 모드에서 동시에 표시되는 것은 아니다. 조건 필터가 있으므로 메뉴 선언과 실제 사용 가능 여부를 구분해야 한다. [E06]

선택 사진용 `CollageMenuView`에는 별도 메뉴 집합이 있다. 일반 사진, 자유형, 사용자 스티커 등의 상태별 배열이 다르며 일부 항목은 조건 함수로 걸러진다. [E05]

| 조작 범주 | APK에서 확인한 메뉴 |
|---|---|
| 사진 교체 | 교환, 교체, 자르기, 삭제 |
| 구도 | 회전, Fit/Fill, 수직·수평 방향 반전 후보 |
| 정밀 조작 | 확대·축소, 왼쪽·오른쪽·위·아래 |
| 레이어 | 잠금, 앞으로·뒤로 보내기 |
| 추가 편집 | 필터, 윤곽선, 지우개, AI 자르기, 3D Popout 등의 선언 |

`Vertical`/`Horizon`은 메뉴 이름·아이콘 수준에서 확인했다. 실제 반전 축, 회전 단위, 확대 배율과 이동 간격은 이번 조사에서 확정하지 않았다. `W0()`는 상황에 따라 회전 문구와 아이콘을 바꾸며, 선택 메뉴가 열릴 때 다른 패널의 표시 상태와 높이도 조정한다. [E05, E07]

**SB 적용:** 사진을 선택하면 자주 쓰는 `교체 / 교환 / 자르기 / 회전 / 반전 / 맞춤·채움`을 바로 제공하고, 세부 조작에 `잠금 / 확대·축소 / 방향 이동 / 앞뒤`를 둔다. 사진이 선택되지 않았을 때는 전체 설정을 보여 준다. 이 배치는 제안이며 GridArt의 정확한 화면 복제안은 아니다.

### 2. 레이아웃 설정을 짧은 탭으로 묶음

`fragment_grid_layout.xml`의 실제 하위 탭 순서는 다음과 같다. [E02]

**템플릿 → 레이아웃 → 비율 → 마진 → 테두리 → 배경 → 적용**

탭 아래에는 132dp 높이의 하위 Fragment 영역이 있다. 레이아웃과 비율은 RecyclerView로 구성한다. `fragment_margin_layout.xml`은 130dp 영역에 다음을 모은다.

- 바깥 여백 슬라이더 + 수치
- 사진 사이 간격 슬라이더 + 수치
- 모서리 슬라이더 + 수치
- 초기화 / 모두 제거 버튼

테두리는 색상 목록과 두께 슬라이더를 별도로 갖는다. 자유형용 전체 설정은 배경·테두리·비율로 축약된 별도 패널이다. [E02]

**SB 적용:** 기본·자유형·디자인 사이에서 비율·여백·테두리·배경을 찾는 위치와 용어를 통일한다. 현재 SB에 이미 있는 기능을 재배치하는 작업이 먼저다. GridArt의 130/132dp를 그대로 고정할 필요는 없고 작은 화면·큰 글자에서는 캔버스와 설정 공간을 함께 확인해야 한다.

### 3. 사진 추가를 두 가지 의미로 구분

`activity_edit.xml`과 `ImageEditActivity.onClick()`에 `btn_add_to_grid`와 `btn_photo_on_photo`가 각각 존재한다. 앞쪽은 갤러리 선택 경로로, 뒤쪽은 별도 사진 추가 경로로 연결된다. 한국어 리소스는 뒤쪽을 사진 속의 사진으로 표시한다. [E02, E09]

**해석:** 그리드의 칸에 사진을 넣는 동작과, 그 위에 겹치는 사진을 추가하는 동작을 UI에서 구분하려는 구조다. 세부 삽입 위치와 좌표 계산은 확인하지 않았다.

**SB 적용:** 템플릿의 빈칸 채우기와 자유 배치 사진 추가를 같은 `+`로 모호하게 만들지 않고, 현재 선택 상태에 맞는 이름과 표시를 준다.

### 4. 제스처와 버튼을 함께 제공

패키지의 도움말 문자열에는 한 번 누르기, 두 손가락 확대·축소, 길게 눌러 드래그하여 교환, 두 번 눌러 전체 사진 표시가 설명되어 있다. `ItemView`에는 `setForbidDoubleTap`, `setForbidSwap`, `setLockSelection`, `getLockTargetItem` 관련 구조가 있고, 터치 처리 smali는 MotionEvent 동작·포인터 수·위치와 별도 제어 객체를 사용한다. [E02, E10]

다만 도움말이 현재 버전의 모든 편집 모드에서 그대로 작동한다는 증거는 아니다. 긴 터치 시간, 드래그 임계값, 이중 탭 결과, 핀치 중심 유지와 경계 복귀 애니메이션은 미검증이다.

**SB 적용:** 사진 내부 구도 이동, 사진틀 자체 이동, 사진 교환을 명확히 나누고, 사용자가 현재 조작 대상을 알 수 있게 한다. 정밀 이동 버튼은 작은 화면에서 미세 조정할 때 도움이 될 가능성이 있다.

### 5. 갤러리와 템플릿 탐색

갤러리 XML에는 앨범 선택, 선택 개수, 선택 사진 RecyclerView, 비우기, 빠른 스크롤, 길게 눌러 미리보기 안내, 제한 사진 권한 추가 안내가 있다. 하단 시트용 갤러리도 별도로 존재한다. 템플릿 필터에는 **사진 수와 비율** 목록이 있다. [E02]

현재 SB도 앨범·선택 순번·선택 모음·제한 권한 안내와 사진 수·비율 필터를 이미 제공한다. 이 항목은 신규 기능 차이보다 선택 영역의 높이와 캔버스 유지 방식을 참고할 대상으로 보는 편이 적절하다.

### 6. 글자와 사진 보정

글자 패널에는 키보드, 글꼴, 스타일, 프리셋, 곡선, 추가 항목이 선언되어 있다. 글자 세부 XML에는 정렬, 굵게·기울임·밑줄·취소선, 대소문자, 자간·행간 슬라이더가 있다. [E02]

필터는 전체 도구 및 선택 사진 메뉴에 모두 연결 가능한 선언이 있으며, 필터 강도 조절 안내와 별도 편집 패널, `assets/table_*` 자료가 포함된다. 이 사실만으로 해당 파일이 어떤 LUT 형식인지, 정확한 색 변환 결과가 무엇인지는 확정할 수 없다. [E02, E05, E06]

**SB 적용:** 현재 글자 편집에 자간·행간·스타일 프리셋을 추가하는 것은 후순위 후보다. 사진별 밝기·대비·채도·필터는 현재 모델·렌더링에 없는 비교적 큰 확장이므로, 미리보기와 저장 양쪽에 같은 처리를 추가해야 한다.

### 7. 저장·초안

저장 버튼은 `I0()`로 연결된다. 이 메서드는 조건부 초안 저장 분기와 `ImageResultActivity` 전환을 수행한다. 결과 화면 코드는 진행 상태·완료 표시·공유 목록을 구성하고, `ImageEditActivity.saveDraft()`도 별도 초안 관리 객체로 위임한다. [E09, E11]

한국어 리소스에는 1920px, 4096px, 6144px 해상도 안내가 있다. **설정 문구의 존재만 확인했으며 실제 저장 가능 해상도, 무료/Pro 제한, 파일 인코딩·색공간·EXIF·최종 선명도는 검증하지 않았다.**

SB는 이미 긴 변 최대 4096px JPEG 저장 경로를 갖는다. GridArt 문구만 보고 곧바로 6144px로 올리는 근거는 부족하다. 특히 메모리·여러 사진 디코딩과 저장 실패 복구를 먼저 확인해야 한다.

초안 영구 저장은 현재 SB의 홈 복귀 초기화·이력 미보관 정책과 연결된다. 도입하려면 별도 제품 결정을 해야 하며 이번 분석에서는 그 정책을 바꾸지 않았다.

### 8. 스타일과 구현 구조

상단 높이 리소스는 56dp다. 편집 도구 배경은 기본 색상 테이블에서 흰색, night 테이블에서 `#1a1a1e`이며 저장 강조색은 `#487bf9`로 선언되어 있다. 실제 기기에서 테마를 전환해 확인하지는 않았다. [E02]

구현은 Android XML/View 계층과 사용자 정의 사진·배경·낙서 View를 조합한다. 문자열 디코더는 JNI의 `Decoder.decodeBytesNative`를 호출하는 경로가 있다. 일부 설정 자산은 그대로 JSON으로 읽을 수 없었고 전체 레이아웃 좌표·형상·개수를 복원하지 않았다. [E12]

SB는 Compose와 자체 모델·렌더러를 유지하면서 도구 구분·상태 변화·조작 방식만 참고할 수 있다. 참고 앱의 Activity/Fragment 구성이나 JNI 디코딩을 SB에 옮길 이유는 없다.

## 적용 설계 제안

아래는 분석 결과를 바탕으로 한 SB 설계안이며 구현 승인이 확정된 요구사항이 아니다.

| 우선순위 | 변경 후보 | 기대 효과 | 관련 변경 범위 |
|---|---|---|---|
| 1 | 기본·자유형·디자인의 공통 도구 위치/명칭 통일 | 현재 기능을 찾기 쉬움 | 두 편집 UI, 선택 상태, 뒤로 가기, Undo 연결 |
| 2 | 선택 사진의 간단 메뉴 + 정밀 조작 패널 | 교체·구도 조정의 이동 횟수 감소 | 사진 선택·제스처·좌표 변환·잠금 상태 |
| 3 | 디자인 레이아웃도 실제 그림 썸네일 | 글자를 읽지 않고 배치 비교 | 레이아웃 목록 UI와 미리보기 |
| 4 | 사진별 밝기·대비·채도/필터 | 콜라주 안 사진의 색감 통일 | 사진 상태·직렬화·Undo·미리보기·출력 렌더러 |
| 5 | 템플릿 변경 시 사진 유지, 필요 시 빈칸 채우기 | 여러 디자인을 빠르게 비교 | 슬롯 대응·사진 수 차이·자르기 상태·배경 처리 |
| 별도 결정 | 영구 초안·사용자 템플릿 | 재편집 | 현 보관 정책·URI 수명·프로세스 종료 복원 |

권장 화면 상태는 다음과 같다.

| 상태 | 하단에 보여 줄 내용 | 완료/뒤로 처리 |
|---|---|---|
| 전체 편집 | 배치·비율·여백·테두리·배경·글자·장식 | 편집기 종료 |
| 사진 선택 | 교체·교환·자르기·회전·반전·맞춤/채움 | 선택 해제 후 전체 도구 복귀 |
| 정밀 조정 | 이동·확대축소·잠금·겹침 순서 | 적용 또는 취소 |
| 글자/장식 선택 | 해당 항목 속성·삭제·순서 | 선택 해제 또는 설정 닫기 |

단계적 적용 시에는 UI 재배치와 새 렌더링 기능을 따로 검토하는 편이 변경 영향을 판단하기 쉽다. 특히 기존 `CollageDesignDocument`와 공통 렌더러를 유지하고, 패널의 임시 값·적용·취소 및 한 번의 제스처가 Undo 한 단계가 되는 규칙을 일관되게 다뤄야 한다.

구현 이후 확인할 인접 기능은 템플릿 칸 채우기, 자유형 겹침 선택, 사진 재선택 취소, 홈 복귀 초기화, 미리보기와 저장 결과 일치다. 사진 수 0/1/15장, 부분 사진 권한, 사라진 URI, 고화소 입력, 화면 재생성, 빈 템플릿 슬롯도 확인 대상으로 남긴다. 이번 조사에서 이 동작들을 새로 실행·테스트한 것은 아니다.
