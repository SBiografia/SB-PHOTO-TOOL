## 구현 방향

- 그리드: 원본 위 이동/크기 조절 crop 영역, 프리셋과 1~10 가로·세로 직접 입력, 저장 순서 표시. 한 타일은 기존과 같이 정사각형이며 SNS의 최신 프로필 표시 비율을 보장하지 않는다.
- 압축: 선택 사진 확인, 용량/해상도/추가 설정 분리, 빠른 프리셋과 검증된 입력, 한 장 테스트와 실측 용량 비교. `%`는 해상도 비율임을 명시한다.
- GIF: 사진/영상 선택, 재생 미리보기, 사진 순서·삭제, 영상 구간 조절, 속도와 해상도 분리. 사진 표시 시간과 영상 FPS를 동시에 보여 주지 않는다.
- 세 화면 모두 원본을 보존하고 결과만 저장한다. 새 화면에서 저장하면 기존 홈의 진행/완료 표시로 연결한다.

## 반영 파일과 동작

- `ui/split/SplitEditorScreen.kt`, `media/GridCrop.kt`, `media/GridRenderer.kt`, `model/JobSpec.kt`: 이동·손잡이 조절 영역을 정규화 좌표로 저장해 실제 분할에도 적용한다. 예전 작업 JSON에는 crop이 없어도 기존 중앙 자르기로 처리한다.
- `ui/compress/CompressEditorScreen.kt`, `media/MediaProcessor.kt`: 한 장 테스트와 실제 저장이 동일한 압축 함수를 사용한다. 테스트는 갤러리에 파일을 남기지 않는다. 설정/사진이 바뀌면 지난 측정값을 지운다. 충분히 작은 같은 형식의 사진은 해상도 유지·촬영 정보 보존일 때 재압축하지 않는다.
- `ui/gif/GifEditorScreen.kt`, `GifTiming.kt`: 사진 프레임 재생과 순서/제외, 영상 재생·시작 프레임·구간 슬라이더, 사진 시간/영상 FPS 분리. 사진 미리보기 총 픽셀 예산은 약 12MiB, 개별 최대 긴 변 512px이다. 재생 중이 아닌 영상도 선택 구간의 실제 시작 프레임을 보여 준다.
- `ui/editor/EditorComponents.kt`, `ToolSelectionState.kt`: 큰 미리보기, 48dp 조작 영역, 작은 화면/키보드에 맞춘 패널 높이, 도구 패널 접기. 폴더의 대량 URI 목록은 저장 상태 Bundle 대신 ViewModel에 둔다.
- `MainActivity.kt`, `worker/ToolboxWorker.kt`: 새 화면 연결, 저장 후 홈 진행 표시, 압축 완료 용량 비교, 작업 시작/완료/실패 로그. 폴더는 읽기 권한만 유지한다. 100장을 넘긴 GIF 선택은 몰래 잘라내지 않고 안내 후 이전 선택을 유지한다.
- `app/build.gradle.kts`, `README.md`: 버전 `1.2.0 (3)` 및 사용/검증 경계 갱신. 런타임 라이브러리나 인터넷 권한 추가 없음.

콜라주 편집 화면/상태/렌더러는 변경하지 않았다. 화면 폐기 시 Compose가 소유한 미리보기 bitmap을 강제로 recycle하지 않는 기존 안전 규칙을 유지한다.

## 검증

### 검증 중 발견 — 2026-09-30 KST

- 사진/영상 GIF 실저장 테스트 모두 `Image does not fit in screen` 재현. 기존 `rgbMatrix`가 `[width][height]` 배열을 전달했지만 GifEncoder는 행 우선 `[height][width]`를 받는다. 정사각형이 아닌 GIF가 실패하고 정사각형은 전치되는 공통 원인을 수정했다. 프레임 수·해상도·표시 시간을 읽는 회귀 테스트를 추가했다.
- 이동하는 개별 손잡이 안에서 좌표 차이를 누적하면 크기 변경 후 좌표계가 다시 움직인다. 그리드 전체의 고정 좌표에서 제스처 시작 영역과 누적 이동량을 사용하도록 조정했다.
- 테스트 입력창을 닫는 IME 전환 중 좌표를 주입하면 드래그가 취소될 수 있어 UI 테스트는 캔버스 좌표가 안정된 후 드래그한다. 작은 화면의 가로 스크롤 프리셋도 보이도록 스크롤한 뒤 누른다.
- 360×640dp 화면에서 도구가 미리보기를 과도하게 차지하는 것을 스크린샷으로 확인했다. 작은 화면의 설정 영역을 112dp로 줄이고 패널 접기/펼치기를 추가했다.

### 실행한 검증

- JVM 단위 테스트 22개 통과: 기존 콜라주/로그/순서와 새 crop의 1~10 격자 비율·경계·반복 제스처·JSON 호환, GIF 순서/시간 계산.
- Android API 37 에뮬레이터 전체 18개 통과: 기존 콜라주 7개와 새 UI/실제 저장 테스트 11개. 최종 배포 소스 재실행도 `OK (18 tests)`이며 전체 결과는 `build/tool-ux-reference/final-instrumentation.txt`에 있다.
- 720×1280px, 320dpi(360×640dp)의 작은 화면에서 새 편집기 6개 재실행 통과. 패널 접기가 미리보기 표시 크기를 실제로 늘리는지도 검증한다.
- 압축: 테스트 시 갤러리에 출력 없음, 실제 출력과 측정 바이트 일치, 원본 바이트 유지, EXIF 촬영 날짜 보존, 재압축 없는 복사 바이트 일치.
- 분할: 지정된 녹색 구간만 4개의 240×240 조각으로 저장됨을 픽셀 검사. 사진 이동/영역 크기 변경 및 화면 복원 후 저장 좌표 검사.
- GIF: 세로 사진 GIF 3프레임/1.5초/96×160, 영상 구간 GIF 5프레임/1초/160×120을 GIF 바이너리에서 검사. 유실된 사진 재시도/제외, 재생/일시정지, 순서 및 속도, 영상 구간 슬라이더 검사.
- Debug APK 및 AndroidTest APK 빌드 성공. Android Lint 오류 0, 경고 33(의존성 업데이트·KTX 권고·의도적인 종료 로그 동기 기록 등). SDK/의존성 일괄 업그레이드는 하지 않았다.
- 스크린샷 확인: `build/tool-ux-reference/tools-qa`, 작은 화면은 `build/tool-ux-reference/compact/tools-qa`. 전부 생성한 테스트 이미지/영상이며 사용자 사진을 테스트 출력으로 배포하지 않는다.

### 미검증 및 제한

- 연결된 실제 기기는 ADB 미승인 상태여서 이번 빌드의 실기기 테스트는 하지 않았다. Android 10 실기기, 제조사별 선택기, 클라우드 URI 공급자, 매우 큰 폴더/장시간 영상의 성능은 별도 확인이 필요하다.
- GIF 미리보기는 계속 반복한다. 동영상 미리보기는 원래 프레임 속도이며 결과 GIF의 색상 양자화/파일 용량을 그대로 재현하지 않는다. 결과의 프레임/시간/크기는 별도 저장 테스트로 확인했다.
- EXIF 보존/해상도 우선으로 최대 용량을 초과할 수 있으며 테스트 및 완료 메시지로 알린다. 사진 크기 유지도 기존 메모리 안전 범위(일반 4096px, 해상도 우선 8192px)를 따른다.
- 압축 폴더 선택은 프로세스 종료 후 복원하지 않는다. 앱 재실행 때는 다시 선택해야 하며 원본을 수정하거나 삭제하지 않는다.

## 압축 설정 화면 조정 — 2026-10-01 KST

- 압축 미리보기와 도구 패널이 편집기 가용 세로 영역을 나눠 쓰도록 조정했다. 기존보다 미리보기 영역은 절반 수준으로 줄고, 용량 설정이 더 넓어지며 작은 화면에서도 패널 안쪽은 스크롤된다.
- 용량 프리셋은 500 KB, 1 MB, 2 MB로 통일하고 직접 입력은 KB 단위 텍스트 필드로 유지한다.
- 현재 앱의 인코딩 경로는 JPEG/WebP 품질 기반 재인코딩, PNG 무손실 인코딩, 그리고 목표 용량 우선 모드에서의 단계적 해상도 축소다. 같은 형식·해상도 유지·메타데이터 보존이며 이미 목표 이하인 입력만 원본 바이트를 그대로 복사한다.
- 갤러리 페이지는 앨범의 예상 사진 수를 이용해 MediaStore의 한 페이지 결과가 조기에 끝난 경우도 다음 페이지를 계속 요청한다. 끝부분 자동 로드 임계값을 조정하고 수동 “사진 더 불러오기” 복구 경로를 둔다.
- 이번 변경은 `:app:compileDebugKotlin` 빌드 확인을 수행했다. 계측 회귀 테스트와 실기기 대량 앨범 검증은 수행하지 않았다.
